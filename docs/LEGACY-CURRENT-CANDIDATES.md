# Exact current catalog candidates for legacy notes

The private S-03 correlation report found 59 site preleads with one row in the 19 deployed catalog HTML files. That is useful evidence for a reviewer, but the old key lacks a trusted profile reference. The old sales path resolver places expo projects under `~/users/<USER_ID>/`; the first path segment of a verified catalog receipt identifies that **old owner namespace**. It does not establish the matching user profile in the new agent.

`src/legacy-current-candidates.js` reopens every candidate's exact HTML object from the byte-verified private backup. It checks the source SHA-256, manifest path and event, parsed `EX` row index and original ID, and the old bot's normalized site prelead key. One mismatch stops the whole list. The private result records source SHA, path, event, row, original company ID and old `USER_ID` namespace, with `trustedProfileRef: null` and `pending_profile_owner_review`. It also preserves the other 93 preleads as quarantine: three current normalized-key collisions, nine historical-only matches, and 81 with no catalog row. Forty-three old deal messages belong to the last group. Two of the 59 unique current candidates have an ID unsafe for the target catalog link rule and need explicit catalog identity resolution.

`node scripts/legacy-current-candidates.mjs CORRELATION_REPORT_JSON INDEPENDENT_RECEIPTS_JSON CURRENT_CATALOG_BACKUP_DIR NEW_PRIVATE_OUTPUT_JSON` reproduces the list. It verifies the independent correlation report digest, all catalog backup bytes and the three source receipts before writing an owner-only file outside Git. Console output contains only aggregate counts. A private run produced the same byte digest as a separate local builder. Invented golden tests cover the exact-row case, changed bytes, stale source revision, wrong row/path and private output permissions.

A reviewer must still establish the trusted old-to-new profile mapping, settle the two unsafe IDs and any catalog build identity conflicts, verify the 59 proposed note timelines and any existing provider deals, and reconcile notes written after the initial D1 export. The candidate list performs no note attachment, D1 import, Weeek call or browser route change. The 93 quarantined preleads keep their original messages and deal links in the private SQL backup until reviewed individually.
